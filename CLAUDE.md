# Review Desk

A desktop app (Electron, macOS/Linux/Windows) that turns a GitHub review load into one queue. It is early: the owner is still working out what they want, so keep changes small and easy to undo. Prefer plain code over new abstractions.

Product principle: the main page lists only what the owner must act on, as one ordered list, one line per item (the title, quietly its repo#number, who it's from and a PR's stage, its age, and at most one call to action naming the action, e.g. "Ready for review" on their own draft or "Reply" on their PR whose only action is answering someone; no why, AI gist or chips). PRs handed off with `m m` live in Merging, never on the main page; the coordinator (a background Claude Code session the desk starts and wakes, README → Coordinator) gets them merged, and one comes back only when it hands it back. What was sorted away is under Later. Maximize automation: new things become rules or settings, not new pages. State stays on the desk (`src/desk.ts` decides what's on the queue, its order and what notifies; clients only render), so the tray, MCP and notifications agree and another client could render the same. Design: an informational app with a calm palette and no highlighter; colour only where it carries information (CI failing, a merge conflict, changes requested, an AI review's risk) and on calls to action (the accent: filled on the one to press, tinted on a row's); bigger type that uses the window's width; sentence case, no boxed chips. Themes are CSS token sets picked per device (Settings → Appearance, kept by the desktop app, or in localStorage in a browser), not desk settings. After any UI change run `npm run shots` and look at `.shots/` in light and dark and each theme; don't call a design change done from code alone.

## Run

```bash
npm run app        # the desktop app from the repo
npm run app:dev    # the desktop app running from this checkout (below); restarts on electron/ changes
npm run dev        # server --watch + Vite in a browser at :5173
npm test           # node:test, no network
npm run check      # everything CI runs: prettier, oxlint (type-aware), stylelint, tsc, knip, tests
npm run format     # prettier --write
```

`DESK_HOME` and `DESK_PORT` point any of these at a scratch home and port; the default is `~/.review-desk` on 47823.

Run from a checkout: Settings → Desktop app → Run from a checkout (`app.source`, or `DESK_SOURCE`) set to `~/code/review-desk` makes the packaged app run from that checkout, so a merge to main lands live without a restart (keep main startable). The app keeps its window, tray, hotkey and login item, and runs the desk from the checkout with `node --watch` (a change under `src/` restarts only the desk; the window stays on its view and reconnects) and the UI on a Vite dev server (a change under `web/` is hot reload). A change under `electron/` needs a rebuilt app (`npm run dist:mac`). A desk that fails to start shows its last lines in the window and starts again on the next change or `npm install`; both processes' output is in `~/.review-desk/live.log`. It needs `node` on your login shell's PATH; without it the app runs its own desk and Settings says why.

## Rules

- The desk writes to GitHub only through `src/github/write.ts`, and only on an explicit user action in the UI (today: approve, `a a` in a PR's review; Send twice on your reply to a conversation in a PR's review; Ready for review, `a a` on your own draft's row or in its review; the More menu, `.`, on the selected row or in a review: close (`c c`), convert to draft (`d d`), merge now (`m m`, pinned to the head the desk judged ready) and reopen (`r r`) a PR you opened, close an issue you opened or are assigned (`c c`), and request changes on someone else's PR in its review (`x`, then send twice)). Which of the More menu's an item allows is the desk's call (`Desk.actions()`), on the real author: a bot's `via` line never unlocks one; it refuses any other with 409. Its `ALLOWED` map is the complete list of mutations; adding one is a product decision, not a refactor. `m`, `b` and a hand-back write nothing; the coordinator is the owner's own Claude Code session, which the desk starts and wakes but doesn't run. Every write is logged and recorded in the action log. Nothing an agent can call (MCP tools, the CLI) reaches it, and the read client in `src/github/client.ts` keeps refusing every `mutation`. Tests use a fake write client; live checks stub it (`startServer({ writer })`) and never touch real PRs.
- Node runs the `.ts` files directly (type stripping): no enums, namespaces or parameter properties; relative imports end in `.ts`; type-only imports use `import type`.
- Comments: one line, only for a non-obvious why.
- Add or update a test in `test/` (or `web/test/`) for logic changes. Tests never run a real agent: the judge and coordinator tests put a fake `claude` in a temp dir.
- `npm run check` must pass before you're done (the pre-push hook runs it; CI runs it on macOS, Linux and Windows). Fix findings, don't silence them: an inline `// oxlint-disable-next-line <rule> -- <reason>` only where the rule is wrong for that line. Don't loosen `.oxlintrc.json` or the tsconfig flags.
- TypeScript 7 (the Go compiler) has no JS API, so typescript-eslint can't run; type-aware linting is oxlint + tsgolint.
